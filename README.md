# PotatoVN 自定义云备份

将 PotatoVN 游戏资料和存档备份到自己的 **WebDAV、OneDrive 或 Google Drive**。插件直接连接云端，不需要网盘同步客户端，不使用官方服务器的 100 MB 对象存储额度。

## 安装和首次配置

1. 构建产物位于 `PotatoVN.App.PluginBase/artifacts/PotatoVN-DataBackup.pvnplugin.zip`，在 PotatoVN 的插件管理中导入并启用。
2. 打开侧边栏“云备份”，或在插件管理中点击“打开云备份设置”，进入独立页面。顶部标签栏、底部操作按钮、进度和结果固定显示，只有中间的设置内容滚动。
3. 在“连接云盘”选择云盘类型。WebDAV 填地址、账号和应用密码，再点“保存并测试连接”；微软和谷歌填写自己的桌面 OAuth 应用配置，点“登录云盘并测试”。首次无需先添加渠道；之后切换渠道就会用于备份与恢复，未保存的编辑会先询问如何处理。详见 [云端渠道配置](doc/cloud-providers.md)。
4. 在“备份内容”勾选手动备份类型，并分别选择“本地游戏”“非本地游戏”；两项都选时包含全部游戏和以后新增的条目。“仅备份指定游戏”可进一步缩小范围，支持搜索、只看已选及批量选择筛选结果，切换搜索或本地/非本地范围会保留之前的指定游戏勾选。
5. 点击“立即备份”（会同时保存设置，使用手动备份内容）。需要自动运行时，再到“自动备份”开启定时或游戏退出后备份，独立勾选自动备份内容并保存设置。未保存的修改在底部提示；操作结果只在对应页签显示，成功和普通提示在 4 秒后自动收起，错误和警告保留至手动关闭；运行进度和日志仍在底部查看。

新渠道会自动建立 `PotatoVN_Data`，无需配置备份目录。旧渠道继续使用原有目录与父路径，避免升级后找不到历史；不会自动搬移已有云端文件。

“各游戏存档位置”支持名称、目录或来源 ID 搜索，以及“已配置存档”“未配置存档”“本机目录有效”勾选筛选。前两项互斥，“本机目录有效”可组合勾选；都不勾选时显示全部游戏。列表用状态标签区分游戏，隐藏安装路径；宽窗口在列表右侧显示本地缓存封面与存档详情，窄窗口上下排列。当前运行内重开设置会沿用上次操作的游戏。存档路径以小字显示，长路径省略中段，悬停可查看完整路径。

未配置存档位置的游戏不会被插件擅自扫描整个游戏目录。宿主提供的有效存档位置及游戏目录内直接的 `save` 文件夹会作为候选展示，悬停可查看完整路径，点击“检查并添加…”并保存后才参与备份；刷新或“重新检查存档位置”会重新获取候选。也可直接选择实际存档文件夹或单个文件，插件自动识别相对路径规则。选择器优先打开当前游戏关联的根目录；未关联或目录失效时，回退到上次使用的位置。文件和文件夹分别记住浏览位置，编辑弹窗中的浏览按钮遵循相同规则。例如安装目录为 `D:\Games\某游戏` 时，实际存档可以是 `D:\Games\某游戏\save`，备份位置明确显示后者。

## 备份进度与本机目录

备份完成结果按“本次更改、实际上传、存档概况”分行显示，只列发生变化的资料、图片和存档类型；无变化时不展开变化项。未找到存档的游戏汇总数量，不逐个刷屏。底部日志合并连续的存档校验和上传进度，保留最终结果及维护问题。

状态页的“云备份任务”覆盖导出、整理、资料/图片/存档上传、完整版本发布及历史清理；可在状态页或插件底部取消。百分比按处理阶段分配，上传阶段随已处理文件更新，同时显示上传、复用文件数及成功上传字节，不表示预计剩余时间。

“导出数据任务完成”只表示宿主已经生成中间 ZIP；它后面仍需整理和上传，不能据此判断云备份成功。完整流程结束后才显示“云备份任务完成”，并可在“恢复备份”读取对应云端版本。每次任务的 `work/` 临时目录在结束（包括失败、取消）后清理，不长期保留每次备份的重复本地副本。下次备份、读取历史或准备恢复时，会额外回收超过24小时的异常退出工作目录；占用或权限问题会提示，下次操作再重试。清理仅针对插件生成的临时目录，待恢复存档、回滚副本、待导入文件、配置和凭据不在此范围内。导出通知里的中间 ZIP 路径不会永久保留。

在“连接云盘 → 更多选项”点击“打开本机数据目录”，可直接找到配置、待恢复区和回滚副本。普通运行的数据目录位于 `%LOCALAPPDATA%\PotatoVN-DataBackup\<宿主数据目录标识>`；商店/MSIX 版本可能将它重定向到 `%LOCALAPPDATA%\Packages\<PotatoVN 包族名>\LocalCache\Local\PotatoVN-DataBackup\<标识>`。通知中的路径可能仍为重定向前的路径，找不到该表面路径不代表没有创建本机数据。

## 可以选择的内容

游戏信息、封面、评价与评论（含游玩状态）、游玩时间与次数、角色资料与图片、头图、游戏库与分类、制作人员、主页布局、常规设置、游戏存档。

手动与自动备份分别保存内容选择；定时和游戏退出后备份共用自动备份内容。例如手动备份全部资料，自动只备份游戏存档。两者共用“备份内容”页的游戏范围与存档位置：本地游戏指当前关联有效游戏目录的条目，未关联或目录已失效的条目归入非本地游戏。指定游戏与本地/非本地范围取交集；备份游戏相关内容时，至少选择一类范围。

旧配置首次沿用原内容，两类游戏默认都包含；保存后两套内容选择独立生效。未勾选字段和图片、范围外游戏及其分类引用不进入对应备份包。常规设置采用白名单，不收集账号令牌、密码、同步游标或机器专属运行路径。

定时和游戏退出触发独立开关，默认关闭；默认间隔 6 小时、退出延迟 10 秒。应用关闭后不运行后台备份服务。所选游戏仍运行、存档位置缺失或文件不完整时，不生成空存档替代已有进度。

## 合包增量、索引与本机占用

新备份默认使用 **v3 合包增量**。游戏资料直接采集为轻量 JSON，图片和存档引用实际源文件；日常备份不再先生成完整宿主 ZIP、解压后再打包。恢复仍使用已有的原生导入、匹配及待恢复区流程。

- 图片按路径、大小、修改时间复用本机 SHA-256 缓存，每7天在备份时重新读取校验；存档每次都计算内容摘要。仅有修改时间变化、内容未变时不上传。
- 变化的小文件跨游戏合包，图片包按约32 MiB原始内容、资料/存档包按约8 MiB原始内容控制，每包最多256个不同内容文件；达到大小阈值的单文件独立GZip保存。只上传本次变化内容，旧文件继续引用旧包，不因一个小存档变化重传整个旧包。
- 文件配方保留完整路径/长度/摘要，内容摘要映射到包。每个版本独立列出完整引用，恢复无需从首次开始逐轮重放增量。重命名和删除可以仅更新索引；空或缺失存档位置仍沿用完整历史，不用空文件覆盖进度。
- 每台设备有两份带内容校验和提交代数的压缩JSON索引。包全部上传后才覆盖非当前槽，并读回校验；索引半写可回退，两个槽都损坏时停止写入和清理。相同设备、相同渠道通过本机文件锁串行写入。
- 日常读取两份索引并按桶批量检查包的存在与长度，不逐文件发查询，也不遍历所有旧清单。单桶最多500个对象，按需增加分桶；内容无变化时不新建云端版本，只更新本机成功检查时间。
- 软件快照、存档分别按保留数量维护。两个有效索引共同保护包引用；过期候选写入索引，删除失败可重试。必要时会在下一次无变化检查中推进索引，以释放已过期引用。

```text
PotatoVN_Data/
├─ v1/、v2/                              # 旧格式，继续支持读取恢复
└─ v3/
   ├─ devices/<设备ID>/state-a.json.gz
   ├─ devices/<设备ID>/state-b.json.gz
   └─ objects/<设备ID>/<分桶>/<包SHA256>.zip 或 .gz
```

本机仅长期保存配置、图片摘要缓存和必要的状态。图片缓存只保留本轮用到的条目，并有数量及约16 MiB预算限制，不保存完整数据副本。待上传包流式生成、上传完成即释放，本次工作目录在成功/失败/取消后清理；超过24小时的异常残留在下次操作回收。待恢复区、回滚副本和待导入文件不属于临时缓存。

### 已验证的请求数量

使用实际WebDAV客户端连接内存服务器，100款合成游戏、500张200 KiB图片、1000个100 KiB存档文件（约200 MiB源数据）的结果：

| 场景 | HTTP请求数 |
|---|---:|
| 首次备份，生成17个内容包 | 30 |
| 跨实例再次备份，完全无变化 | 4，上传0 |
| 一份存档及游玩记录变化 | 7，上传1个变化包及1份索引 |

样本结束后本机持久元数据约193 KB，工作目录没有残留。这是合成协议检查，不是真实坚果云账号测速；样本内容可压缩，不能据此推断真实上传字节或耗时。真实数量取决于文件大小、包数、分桶、历史维护及服务端响应；OneDrive/Google Drive内部API调用数量也可能不同。

坚果云仍采用至少3.1秒的请求间隔，保留429/503有限重试。按间隔折算，30/4/7次请求约为93/12/22秒，另需考虑本机处理和实际传输；其他应用的同账号流量仍可能触发限额。详见[渠道说明](doc/cloud-providers.md)。

### 兼容与限制

- 旧v1/v2历史在用户读取历史时按需列出并可恢复，不在每次v3备份时扫描；不会自动改写或删除旧格式。首次v3需要建立新的合包基础，旧版本保留期间可能额外占用云端空间。
- 新设备没有本机存档时，可按需把其他设备或旧格式的完整存档复制为本设备持有，保留捕获时间和来源设备，避免跨设备清理破坏引用；这会产生一次性下载/上传。
- 图片属性缓存可能暂时漏掉“内容变了但大小/时间未变”的替换，7天内容重校验会重新检查。存档不依赖此缓存，但每次仍需本机读取；大型存档有相应I/O成本。
- 大文件是整文件更新，不是块级差分。恢复小文件需要下载其所在包；包内部分失效空间不会立即释放，首版没有自动重打包整理。
- 快速检查可发现缺失或长度异常，等长损坏在恢复的完整SHA校验时发现。旧历史内容无法从本机补齐时会停止发布/清理，避免把缺失当成功。
- 不自动扫删身份不明的孤立上传；中断后可能留下未引用云端包，同内容重试会重新上传。不要仅凭文件名自行删除仍有引用的包或索引。
- 新格式历史需要新版插件。对象不额外加密，凭据仍仅在本机使用当前用户DPAPI保存，不进入数据包或索引。

## 新设备及部分恢复

“恢复备份”点击“读取云端备份”后会默认选中最新版本，再选择恢复类型；手动游戏对应关系折叠在更多选项中。未选字段、备份中没有的现有游戏和本机有效目录关联均保留。

所有游戏资料都会备份，包括已卸载或只保留信息的条目。新设备选中游戏信息时创建非本地条目；原库路径保存为待映射配置，不根据旧盘符自动链接。已有游戏按 UUID、唯一且不冲突的来源 ID 和明确映射匹配，名称或旧路径不作为自动合并依据。

读取云端版本后，“游戏与存档”会列出该版本的全部游戏，使用与备份内容页一致的游戏名和颜色标签，分别显示“含存档/无存档”和“已匹配/未匹配”。“含存档”来自该版本实际引用的存档，包含沿用的历史存档，不代表本机当前已配置存档位置。旧版本的逐游戏提示收进“备份提示”。

手动对应关系使用左侧云端、右侧本机双栏，窄窗口上下排列。两侧支持游戏名、目录和来源 ID 搜索；云端可组合筛选“含存档”“未匹配”，本机可筛选有效目录。先点击云端游戏，再点击本机目标，检查对应预览后保存。待恢复目标、恢复前确认也使用相同的名称与状态标签列表；搜索文字必须通过点击候选确认，不能直接当作对应关系。

恢复前，如果存在尚无明确云端对应关系的本地条目，会只列出这些本地游戏。每行可以选择一个云端游戏，或保留“不关联”；全部已匹配、空白新设备、没有云端游戏或仅恢复常规设置时，不显示这个选择框。同一快照中的云端条目和本地目标必须一一对应，历史版本的多个旧身份仍可映射到同一游戏。

- 不关联的本地条目保留；未关联的云端游戏在勾选“游戏信息”时正常创建为非本地条目，存档进入待恢复区。未选游戏信息时，不为它创建资料。
- 不关联的存档任务会记住本次排除的旧本地条目，跨重启保留，避免又被来源 ID 自动配回。之后可在“游戏对应关系”或待恢复区明确指定目标。切换对应游戏时会清除旧自定义目标路径和恢复状态，避免串用另一游戏的位置；同一目标的日常刷新保留已确认路径。
- 如果云端游戏已对应一份恢复出来的资料，而你把它改选到原有本地游戏，会再次确认合并。保留所选目标的本地目录和现有字段，再覆盖本次勾选的云端字段；冗余资料记录的库、分类、制作人员、主页和待恢复任务引用会迁移。不删除游戏文件，也不自动写入存档。
- 冗余记录必须尚未关联有效本地目录，或与目标指向同一目录。两个不同有效目录、相关游戏运行中时，不能执行这项合并。资料合并需要重启，导入前的原始数据保留在宿主回滚副本中。
- 直接链接本地目录不会触发资料合并。已出现两份游戏资料时，可在下一次恢复前选择云端游戏对应的原有本地条目，并确认上述合并。

关闭关联选择框或第二次合并确认不会保存本次选择、下载存档或启动导入。

游戏库可在“游戏库关联”选择本机对应根目录，检查后完成关联。软件资料导入使用宿主的重启导入流程；插件配置、已安装插件记录及待恢复区在本机保留。语言和部分启动期显示设置可能还需再启动一次才能生效。

宿主内部导出、导入接口通过集中兼容层调用；当前版本以此仓库的宿主接口为兼容目标。上游接口改变时需要适配，不承诺所有旧版宿主均可运行。

## 待恢复区

**只下载存档不会直接覆盖游戏目录。**游戏没有关联有效本地目录时，游戏根目录、AppData 和 Documents 存档都进入待恢复区。之后关联游戏只产生提示，再由你选择版本和目标位置手动恢复。

- 游戏根目录位置按照新的本机根目录解析。
- AppData、LocalAppData、LocalLow 和 Documents 使用本机实际用户目录，支持文档重定向。
- 自定义位置需要指定本机目标，不使用旧电脑的绝对路径。
- 每个存档位置分别显示待关联、待指定位置、可恢复、已恢复或失败。
- 状态使用带文字的不同颜色标签，与游戏名优先同行；渠道、时间和存档路径分层显示，条目之间留有间距。长路径保留头尾，悬停可查看完整位置。
- 历史游戏对应关系、待恢复目标与恢复前关联确认均可搜索游戏。输入名称只用于筛选，必须选中候选后才确认对应关系；同一快照仍执行一一对应校验和必要的二次确认。
- 内容相同时跳过；再次恢复旧版本时重新检查实际内容，允许明确回退。替换前保留原文件副本，失败回滚。

“待恢复存档”中可以查看实际占用、游戏/版本数量，按游戏、版本和状态筛选，并显示选择数量。恢复前请只选择同一位置的一个版本；多个版本指向同一目标时会阻止恢复。清理操作折叠在“管理暂存空间”中，可清理已恢复项目、所选项目或全部项目。清理未恢复数据前会确认；正在使用的项目不能清理。

**清理只删除本机暂存副本和任务，不删除云端版本、游戏资料或实际游戏存档。**若云端版本仍在，可以重新下载。

存档恢复的原始副本放在本机插件数据目录的 `rollback/` 下，不属于待恢复区。源存档或目标路径经过符号链接/目录联接时，首版会要求改用明确的实际目录，避免替换链接本身。

## 开发与验证

需要 Windows、.NET 8 目标框架和 Visual Studio 的 WinUI/MSBuild 工具链。独立核心和测试程序没有额外测试框架依赖。

```powershell
# 核心与恢复回归（只用临时合成数据）
```
