# PotatoVN 自定义云备份

将 PotatoVN 游戏资料和存档备份到自己的 **WebDAV、OneDrive 或 Google Drive**。插件直接连接云端，不需要网盘同步客户端，不使用官方服务器的 100 MB 对象存储额度。

## 安装和首次配置

1. 构建产物位于 `PotatoVN.App.PluginBase/artifacts/PotatoVN-DataBackup.pvnplugin.zip`，在 PotatoVN 的插件管理中导入并启用。
2. 打开侧边栏“云备份”，或在本插件设置中打开同一界面。
3. 在“渠道”添加配置，设为当前渠道。WebDAV 填地址和应用密码；微软和谷歌需要自己的桌面 OAuth 应用配置，再通过系统浏览器登录。详见 [云端渠道配置](doc/cloud-providers.md)。
4. 在“备份内容”勾选类型，选择全部或指定游戏，并检查每个游戏的存档位置。支持一个游戏多个文件或目录。
5. 先执行一次手动备份。需要自动运行时，再开启定时备份或游戏退出后备份。

未配置存档位置的游戏不会被插件擅自扫描整个游戏目录。宿主已有检测结果时会提供候选位置，请在界面检查并保存。

## 可以选择的内容

游戏信息、封面、评价与评论（含游玩状态）、游玩时间与次数、角色资料与图片、头图、游戏库与分类、制作人员、主页布局、常规设置、游戏存档。

手动、定时和退出游戏三种触发方式共用一份类型和游戏范围配置。未勾选字段和图片不进入对应备份包。常规设置采用白名单，不收集账号令牌、密码、同步游标或机器专属运行路径。

定时和游戏退出触发独立开关，默认关闭；默认间隔 6 小时、退出延迟 10 秒。应用关闭后不运行后台备份服务。所选游戏仍运行、存档位置缺失或文件不完整时，不生成空存档替代已有进度。

## 云端目录与文件

```text
PotatoVN-DataBackup/v1/
├─ repository.json
├─ snapshots/<设备ID>/<时间戳_版本ID>/
│  ├─ manifest.json
│  ├─ data.zip
│  └─ media.zip
└─ saves/<游戏备份ID>/<设备ID>/<时间戳_版本ID>/
   ├─ manifest.json
   └─ save.zip
```

- `data.zip` 按类型保存 JSON，仅保留所选字段和匹配游戏所需的最小标识。
- `media.zip` 保存本快照使用的图片；没有图片时不生成。图片包在不同软件快照之间不共享。
- `save.zip` 按 `roots/<位置ID>/` 保存一个游戏的多个存档位置；清单记录相对路径规则、原始备份时间及 SHA-256。
- 清单在数据文件上传成功后发布。没有清单的中断上传不会被列为成功备份。
- 存档内容和位置规则都没有变化时引用已有版本，不重复上传。当前设备没有可用版本时可以引用其他设备已有的完整存档，保留原设备及原始时间。
- 找不到本地存档不表示删除云端存档。软件资料和游戏存档分别保留历史：默认软件快照最近 10 份，每个游戏每台设备最近 10 份；被保留快照引用的存档延后清理。

ZIP 是标准压缩格式，首版不额外加密。云盘授权凭据只在本机使用 Windows 当前用户 DPAPI 加密保存，不上传。跨设备使用同一云盘账号和同一 OAuth 应用配置发现历史，但需要在新设备重新授权。

## 新设备及部分恢复

“历史恢复”先选云端版本，再选择恢复类型。未选字段、备份中没有的现有游戏和本机有效目录关联均保留。

所有游戏资料都会备份，包括已卸载或只保留信息的条目。新设备选中游戏信息时创建非本地条目；原库路径保存为待映射配置，不根据旧盘符自动链接。已有游戏按 UUID、唯一且不冲突的来源 ID 和明确映射匹配，名称或旧路径不作为自动合并依据。

恢复前，如果存在尚无明确云端对应关系的本地条目，会只列出这些本地游戏。每行可以选择一个云端游戏，或保留“不关联”；全部已匹配、空白新设备、没有云端游戏或仅恢复常规设置时，不显示这个选择框。同一快照中的云端条目和本地目标必须一一对应，历史版本的多个旧身份仍可映射到同一游戏。

- 不关联的本地条目保留；未关联的云端游戏在勾选“游戏信息”时正常创建为非本地条目，存档进入待恢复区。未选游戏信息时，不为它创建资料。
- 不关联的存档任务会记住本次排除的旧本地条目，跨重启保留，避免又被来源 ID 自动配回。之后可在“游戏对应关系”或待恢复区明确指定目标。切换对应游戏时会清除旧自定义目标路径和恢复状态，避免串用另一游戏的位置；同一目标的日常刷新保留已确认路径。
- 如果云端游戏已对应一份恢复出来的资料，而你把它改选到原有本地游戏，会再次确认合并。保留所选目标的本地目录和现有字段，再覆盖本次勾选的云端字段；冗余资料记录的库、分类、制作人员、主页和待恢复任务引用会迁移。不删除游戏文件，也不自动写入存档。
- 冗余记录必须尚未关联有效本地目录，或与目标指向同一目录。两个不同有效目录、相关游戏运行中时，不能执行这项合并。资料合并需要重启，导入前的原始数据保留在宿主回滚副本中。
- 直接链接本地目录不会触发资料合并。已出现两份游戏资料时，可在下一次恢复前选择云端游戏对应的原有本地条目，并确认上述合并。

关闭关联选择框或第二次合并确认不会保存本次选择、下载存档或启动导入。

游戏库可在“库路径映射”选择本机对应根目录，检查后完成关联。软件资料导入使用宿主的重启导入流程；插件配置、已安装插件记录及待恢复区在本机保留。语言和部分启动期显示设置可能还需再启动一次才能生效。

宿主内部导出、导入接口通过集中兼容层调用；当前版本以此仓库的宿主接口为兼容目标。上游接口改变时需要适配，不承诺所有旧版宿主均可运行。

## 待恢复区

**只下载存档不会直接覆盖游戏目录。**游戏没有关联有效本地目录时，游戏根目录、AppData 和 Documents 存档都进入待恢复区。之后关联游戏只产生提示，再由你选择版本和目标位置手动恢复。

- 游戏根目录位置按照新的本机根目录解析。
- AppData、LocalAppData、LocalLow 和 Documents 使用本机实际用户目录，支持文档重定向。
- 自定义位置需要指定本机目标，不使用旧电脑的绝对路径。
- 每个存档位置分别显示待关联、待指定位置、可恢复、已恢复或失败。
- 内容相同时跳过；再次恢复旧版本时重新检查实际内容，允许明确回退。替换前保留原文件副本，失败回滚。

插件设置中可以查看实际占用、游戏/版本数量，按游戏、版本和状态筛选，清理已恢复项目、所选项目或全部项目。清理未恢复数据前会确认；正在使用的项目不能清理。

**清理只删除本机暂存副本和任务，不删除云端版本、游戏资料或实际游戏存档。**若云端版本仍在，可以重新下载。

存档恢复的原始副本放在本机插件数据目录的 `rollback/` 下，不属于待恢复区。源存档或目标路径经过符号链接/目录联接时，首版会要求改用明确的实际目录，避免替换链接本身。

## 开发与验证

需要 Windows、.NET 8 目标框架和 Visual Studio 的 WinUI/MSBuild 工具链。独立核心和测试程序没有额外测试框架依赖。

```powershell
# 核心与恢复回归（只用临时合成数据）
dotnet run --project PotatoVN.Backup.Tests/PotatoVN.Backup.Tests.csproj

# 恢复前关联选择、重复资料合并与存档待恢复流程
dotnet run --project tests/RestoreMatchingChecks/RestoreMatchingChecks.csproj

# 三渠道模拟协议、凭据及仓库边界（不连接真实账号）
dotnet run --project tests/ProviderProtocolChecks/ProviderProtocolChecks.csproj

# 本机原子配置读写检查
dotnet run --project tests/FilePersistenceChecks/FilePersistenceChecks.csproj

# WinUI 插件与安装包（在 VS Developer PowerShell 中）
msbuild PotatoVN.App.PluginBase/PotatoVN.App.PluginBase.csproj /restore /p:Configuration=Release /p:Platform=x64 /p:RuntimeIdentifier=win-x64
```

验证结果及未验收部分见 [验证记录](doc/validation.md)。首版不包含游戏本体、注册表存档、多设备自动合并，或跨应用重启的分片续传。
